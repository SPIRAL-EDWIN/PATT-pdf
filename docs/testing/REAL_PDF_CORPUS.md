# Real-PDF regression corpus: plan and rules (not yet populated)

**Status (v0.3.7.dev0):** no real-world PDF is in the repository. All automated tests use synthetic
PDFs generated by `tests/fixtures/make_fixtures.py`. This file defines how real samples may be
added, so that results are reproducible and redistribution is lawful. It does **not** claim any
quality result for real documents.

## Admission rules (all required)

1. **Licence permits redistribution in a public repository**, verified from the publisher's own
   page at the time of adding (not a mirror). Acceptable: public domain (e.g. U.S. federal works,
   17 U.S.C. §105), CC0, CC BY 4.0 (attribution recorded), or an explicit written permission that
   is itself publishable. Not acceptable: "free to read", unclear terms, course material, anything
   from the user's own documents, translations, or translation memories.
2. **No personal data** beyond what the publisher made public (no signatures, IDs, addresses of
   private persons). When in doubt, leave it out.
3. **Fonts:** embedded font subsets are accepted only as part of a document whose licence covers
   redistribution of the document; no standalone font files are added.
4. **Size:** each file ≤ 2 MB, whole corpus ≤ 20 MB (Git history is permanent).
5. **Recorded in `tests/corpus/MANIFEST.json`** with: file name, SHA-256, source URL, licence
   (SPDX id or exact statement), licence evidence URL, date checked, who checked, category,
   pages used, and the expected outcome per page (status upper bound, kept numbers, known issues).
   `tools/corpus_check.py` validates the manifest (hashes, required fields, sizes) and is run by
   the test suite whenever the folder exists.

## Categories to cover (one or two documents each)

| Category | What it exercises | Expected outcome (honest upper bound) |
|---|---|---|
| Born-digital report with tables and figures | text replacement, kept numbers, ruled tables | `pass`/`review`; tables are line-based, not structured |
| Form-like page with many short labels | box fitting, shrink, overflow | many `review`, some `fail` |
| Page with underlined headings and links | decoration and link mapping | `review` where mapping is not safe |
| Scanned page (300 dpi) | OCR path, background fill | `review` at best; never `pass` without checking |
| Text drawn as outlines | vector-glyph path | `review`/`fail` |
| Two columns, footnotes, rotated label | grouping and reading order | `review` |

## Procedure for each sample (offline, no translation API)

1. Add the file and its manifest entry; run `python tools/corpus_check.py tests/corpus`.
2. Plan with and without OCR; translate with `--backend pseudo` (layout stress) and with a small
   hand-written `manual` TM for a few lines; render; run `compare` and look at every page image.
3. Record observed statuses and visual problems in the manifest's `observed` field together with
   OS, Python, PyMuPDF and Tesseract versions. Statuses describe what the QA checks found; a
   `pass` is not a claim that the page looks right.
